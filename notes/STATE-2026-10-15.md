## What was found this session

1. **A real parity bug, caught by a new Compose test.** The `[A-Za-z0-9_]`
   secret-name guard existed only in `shared/…/SettingsScreen.kt`; the app module
   keeps its own copy, so Android would submit `API-KEY` and surface a server 422
   while the web build blocked it in the dialog. Fixed (`6c857a5`) — the predicate
   is now identical in both copies.
2. **Compose-web semantics DOM limitation.** After any `AlertDialog` closes, the
   a11y semantics DOM inside the `#composeApp` shadow root collapses to 2 nodes and
   never rebuilds (CDP a11y pulse, mouse move, and canvas click all fail to revive
   it). The app itself is healthy — screenshots at
   `notes/ux-test/shots-v3/nudge-after-cancel.png` prove the Settings screen
   renders correctly after Cancel. Consequence: post-dialog assertions belong in
   the Compose/Robolectric layer, and browser E2E must allow one dialog
   interaction per page load. Worth filing upstream.
3. **Boot cost was over-estimated.** A cold load reaches a populated semantics tree
   in ~2.3 s; the harness's old fixed 25 s wait was ~10× too cautious. Use a
   populated-tree readiness anchor (`roles >= 10`, or a nav button matched by
   **text**, not `aria-label`).
